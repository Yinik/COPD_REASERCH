## 一、研究背景与选题价值

慢性阻塞性肺疾病（COPD）是全球第三大死因，中国患者人数接近1亿。临床医生在日常诊疗中需要快速查阅大量医学文献和指南来获取最新的诊疗知识，但医学文献数量爆炸式增长，人工整理效率极低。

知识图谱能够将非结构化的医学文本转化为结构化的"实体-关系-实体"三元组，帮助医生快速理解疾病、药物、症状、检查之间的关联。本项目聚焦COPD这一高发病专科领域，从权威医学文献中自动抽取实体关系，构建可交互的专科知识图谱，为临床决策支持提供知识基础。

**选题价值**：
- 专科聚焦：不同于通用医学知识图谱（如CMeKG），本项目深耕COPD单一病种，关系粒度更细（13种专科关系）
- 指南对齐：核心数据来源于GOLD 2024、中国COPD诊治指南等权威文献，具有临床参考价值
- 可复现：完整开源了从PDF清洗到图谱构建的全流程代码和数据

---

## 二、研究目标与预期成果

**总体目标**：构建一个覆盖COPD诊疗全流程的专科知识图谱，实现从医学文本到结构化知识再到可视化图谱的端到端流程。

**预期成果**：
1. 处理50篇COPD核心医学文献，提取约49万字清洗文本
2. 构建包含126个医学实体、675条高质量三元组的知识图谱
3. 覆盖13种COPD专科关系类型（药物-治疗-疾病、检查-辅助诊断-疾病、诱发-急性加重等）
4. 部署可交互的Neo4j知识图谱，支持2跳内关联查询
5. 提供端到端演示系统，输入临床文本即可自动抽取实体关系
6. 形成完整的技术文档、测试报告和可复现代码

## 三、技术路线与实现方案

整体技术路线分为四个阶段，形成完整的研究闭环：

```
阶段1：数据处理
  50篇PDF医学文献
    -> pdfplumber提取原始文本
    -> 正则规则清洗（去页眉页脚/去参考文献/去断行）
    -> 49万字规范化文本

阶段2：特征工程（实体识别）
  清洗后文本
    -> 种子词典构建（基于核心文献人工标注+PMI/熵值扩展）
    -> 正向最大匹配实体识别
    -> 126个医学实体（7类：疾病、症状、药物、治疗、检查、危险因素、并发症）

阶段3：模型训练（关系抽取）
  实体列表 + 原文句子
    -> 13类规则模板匹配（基于句法模式和医学关键词）
    -> BERT-base-chinese微调探索（数据不足，作为后续方向）
    -> 生成候选三元组

阶段4：回测验证（质量审核）
  候选三元组
    -> 双人独立人工审核
    -> 医学知识自动审核（基于医学常识规则过滤错误三元组）
    -> 方向规范化（统一疾病为头实体）
    -> 最终675条高质量三元组
    -> Neo4j图谱构建 + 可视化验证
```

**关于方法选择**：
本项目以规则模板为主构建了可复现的基线系统。医学文本中的关系表述具有固定的句法模式（如"X可治疗Y"、"X是Y的症状"），正则模板配合医学关键词即可抓取大部分关系，且规则错误可直接修正，可解释性强。当前标注数据量有限，深度学习方法暂不具备训练条件，留作后续优化方向。

## 四、实验设计与评价指标

### 4.1 实验设计

**消融实验**：设计了6个递进版本验证方案有效性：
- v1 原始规则：基础正则模板
- v2 清洗筛选：增加句子清洗+文献筛选
- v3 改进A：仅保留句子清洗
- v4 最大覆盖：最大化关系覆盖（981条，含大量模糊关系）
- v5 医学细化：引入医学知识审核，从981条筛选至675条
- v6 Final：方向规范化，疾病统一为头实体

**对比实验**：将最终知识图谱与GOLD 2024国际临床指南进行系统对比，计算专科覆盖率。

### 4.2 评价指标

| 指标类别 | 具体指标 | 结果 |
|---------|---------|------|
| 指南对齐度 | GOLD 2024核心推荐覆盖率 | 90.4%（47/52），药物/症状/危险因素/并发症100%覆盖 |
| 抽取准确率 | 人工抽样准确率 | 100条随机抽样，双人审核中 |
| 图谱规模 | 实体数/关系数/关系类型数 | 126实体 / 675关系 / 13种关系类型 |
| 图谱连通性 | COPD可达率 | 91.3%（115/126实体可从COPD出发2跳内到达） |
| 系统性能 | 文本处理速度/内存占用 | 约2000万字符/秒，峰值内存0.71MB |
| 数据质量 | 模糊关系占比 | 0%（Final版本完全消除"相关"等模糊表述） |

详细评价报告见 `GOLD_COVERAGE_REPORT.md` 和 `EVALUATION_REPORT.md`。

## 六、存在问题

1. **标注数据量不足**：675条三元组对于BERT微调来说规模偏小，导致深度学习模型效果不如规则稳定。解决方案：改用LLM few-shot方案，降低对标注数据的依赖。
2. **图谱未完全连通**：126个实体中有11个（8.7%）与COPD无直接路径，主要是部分中药名称。这属于合理范围，不影响核心诊疗路径的展示。
3. **评估量表未覆盖**：mMRC评分、CAT评分等功能性评估工具未纳入当前抽取范围，后续可扩展"评估工具"实体类型。

## 八、运行说明（可复现性）

### 8.1 环境要求

- Python 3.10 或更高版本
- Windows 10/11（开发环境）
- Neo4j Desktop 5.x（可选，用于交互式图谱查看）

### 8.2 安装依赖

```bash
pip install pdfplumber pandas python-docx py2neo networkx matplotlib
```

或直接使用：

```bash
pip install -r requirements.txt
```

### 8.3 一键验证（推荐）

```bash
python verify_project.py
```

该脚本会自动检查：
1. 三元组总数是否为675条、关系类型是否为13种
2. 126个实体的类型分布是否正确
3. Neo4j导入文件是否齐全
4. 图谱连通性（从COPD出发BFS可达率）
5. COPD是否为图谱中心节点

全部通过则显示PASS。

### 8.4 生成可视化

```bash
python generate_kg_viz.py
```

生成6张PNG图片到 `assets/` 目录。

### 8.5 启动端到端演示

```bash
python COPD图谱端到端抽取系统.py
```

支持交互式输入临床文本，自动完成实体识别、关系抽取和Neo4j图谱更新。

### 8.6 Windows一键运行

双击 `run_demo.bat` 即可自动执行验证+可视化+打开结果目录。
