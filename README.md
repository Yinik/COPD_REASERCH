## 项目简介

这个项目是我们小组做的一个COPD（慢性阻塞性肺疾病）医学知识图谱。简单来说，就是**从医学文献里自动抽取出"谁和什么有关系"，然后画成一张图**。

比如文献里写"吸入性糖皮质激素可以治疗COPD"，系统就能自动识别出：
- 实体1：吸入性糖皮质激素（药物）
- 关系：治疗
- 实体2：COPD（疾病）

最后把这些三元组导入Neo4j，做成可以交互查看的知识图谱。

**输入**：一段COPD临床文本或PDF文献  
**处理**：自动识别医学实体 → 抽取关系  
**输出**：结构化三元组 + Neo4j可视化图谱

---

## 核心数据

整个项目处理下来，我们的核心产出是这些：

- **50篇** COPD核心医学文献（GOLD指南、中国诊治指南、专家共识、临床研究）
- **126个** 医学实体，分为7类：疾病(28)、症状(25)、药物(34)、治疗(14)、检查(8)、危险因素(12)、并发症(5)
- **675条** 高质量三元组，涵盖13种关系类型
- **1个** 可交互的Neo4j知识图谱

一开始我们 raw 抽了1247条，后来两个人一条一条审，删掉了差不多一半噪声，最后留下这675条比较靠谱的。

## 技术路线

整个流程大概是下面这样：

```
50篇PDF医学文献
    ↓  pdfplumber提取文本 + 自定义清洗规则
清洗后的纯文本（约49万字）
    ↓  种子词典匹配 + PMI/熵值筛选
126个医学实体（种子词典）
    ↓  13类正则模板匹配
原始三元组 1247条
    ↓  双人独立审核 + 方向规范化
最终三元组 675条
    ↓  生成CSV + Cypher脚本
Neo4j知识图谱
```

### 关于方法选择的说明

我们主要用的是**规则模板**来做关系抽取，而不是端到端的深度学习。原因很简单：

1. **数据不够**：我们自己标了675条，这个量级训BERT根本不够看
2. **医学文本有规律**："X可治疗Y"、"X是Y的症状"这种模式很固定，正则就能抓个七七八八
3. **需要可解释**：规则抽错了能直接改模板，黑盒模型错了都不知道怎么调

当然我们也试了BERT（`bert-base-chinese`），但效果确实不如规则稳定，所以目前还是以规则为主，BERT作为后续优化方向。

### 踩过的一些坑

做这个项目过程中遇到不少问题，记录一下：

- **PDF清洗**：一开始以为pdfplumber直接提取就完了，结果发现页眉页脚、断行、参考文献全混在正文里，后来写了一套正则规则专门处理这些问题
- **CSV编码坑**：Neo4j的`LOAD CSV`对BOM头很敏感，我们用`utf-8-sig`生成的文件导入后属性全空，排查了好久才发现是BOM的问题，后来统一改成无BOM的`utf-8`
- **关系方向搞反**：一开始"并发症-疾病"和"疾病-并发症"都混在一起，后来统一规范成疾病当头实体，图谱才清晰起来
- **图谱不是完全连通**：126个实体里有11个从COPD出发走不到（比如一些孤立的中药名），这是正常的，毕竟不是所有实体都和COPD直接相关

## 怎么用

### 环境准备

- Python 3.10+
- Neo4j Desktop（可选，如果想看交互式图谱）

### 快速开始

```bash
# 1. 克隆仓库
git clone https://github.com/Yinik/COPD_REASERCH.git
cd COPD_REASERCH

# 2. 装依赖
pip install pdfplumber pandas python-docx neo4j requests networkx matplotlib

# 3. 一键验证数据完整性
python verify_project.py

# 4. 生成可视化图片
python generate_kg_viz.py

# 5. 启动Neo4j并导入（可选）
# 详见 关系抽取结果/Neo4j导入教程.md
```

Windows用户可以直接双击 `run_demo.bat`，会自动运行验证+生成图片+打开目录。

### 验证脚本会检查什么

运行 `python verify_project.py` 后，会输出5项检查结果：

1. 三元组是不是675条、13类关系
2. 126个实体的类型分布对不对
3. Neo4j导入文件齐不齐全
4. 图谱连通性（COPD能走到多少实体）
5. COPD是不是图谱的中心

如果全显示 `[PASS]`，说明数据没问题。
