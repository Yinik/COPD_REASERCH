## 项目简介

### 研究背景

慢性阻塞性肺疾病（COPD）是全球第三大死因，中国患者人数接近1亿。临床医生每天要面对海量医学文献，想快速搞清楚"某种药能治什么病"、"某种检查能辅助诊断什么"，靠人工翻文献效率太低了。

知识图谱能把这些散在文献里的知识整理成结构化的"实体-关系-实体"，医生一查就能看到药物-疾病-症状之间的关联。本项目就是干这个的：聚焦COPD这一高发病专科，从权威文献里自动抽实体、抽关系，最后搭成一个能交互查看的知识图谱。

### 选题价值

- **专科聚焦**：不像CMeKG那种大而全的通用医学图谱，我们只做COPD这一个病种，关系粒度更细（13种专科关系），临床参考价值更直接
- **指南对齐**：核心数据来源于GOLD 2024、中国COPD诊治指南、专家共识等权威文献，不是随便从网上爬的
- **可复现**：从PDF清洗到图谱构建的全流程代码和数据都开源了，换一批文献也能跑通

### 预期成果

1. 处理50篇COPD核心医学文献，提取约49万字清洗文本
2. 构建包含126个医学实体、675条高质量三元组的知识图谱
3. 覆盖13种COPD专科关系类型（药物-治疗-疾病、检查-辅助诊断-疾病、诱发-急性加重等）
4. 部署可交互的Neo4j知识图谱，支持2跳内关联查询
5. 提供端到端演示系统，输入临床文本即可自动抽取实体关系
6. 形成完整的技术文档、测试报告和可复现代码

## 核心数据

整个项目处理下来，我们的核心产出是这些：

- **50篇** COPD核心医学文献（GOLD指南、中国诊治指南、专家共识、临床研究）
- **126个** 医学实体，分为7类：疾病(28)、症状(25)、药物(34)、治疗(14)、检查(8)、危险因素(12)、并发症(5)
- **675条** 高质量三元组，涵盖13种关系类型
- **1个** 可交互的Neo4j知识图谱

一开始我们 raw 抽了1247条，后来两个人一条一条审，删掉了差不多一半噪声，最后留下这675条比较靠谱的。

## 技术路线

整个流程大概是下面这样，形成了一个可复现的研究闭环：

```
【阶段1：数据处理】
50篇PDF医学文献
    -> pdfplumber提取文本 + 自定义清洗规则
    -> 49万字规范化文本

【阶段2：特征工程】
清洗后文本
    -> 种子词典构建（基于核心文献人工标注 + PMI/熵值扩展）
    -> 正向最大匹配实体识别
    -> 126个医学实体（7类）

【阶段3：模型训练（关系抽取）】
实体列表 + 原文句子
    -> 13类规则模板匹配（基于句法模式和医学关键词）
    -> 生成候选三元组 1247条

【阶段4：回测验证】
候选三元组
    -> 双人独立人工审核
    -> 医学知识自动审核（基于医学常识规则过滤错误三元组）
    -> 方向规范化（统一疾病为头实体）
    -> 最终675条高质量三元组
    -> Neo4j知识图谱构建 + 可视化验证
```

### 关于方法选择的说明

我们主要用的是**规则模板**来做关系抽取。原因很简单：

1. **医学文本有规律**："X可治疗Y"、"X是Y的症状"这种模式很固定，正则就能抓个七七八八
2. **需要可解释**：规则抽错了能直接改模板，黑盒模型错了都不知道怎么调
3. **数据不够**：自己标的675条，这个量级训深度学习模型不够看，暂时不具备条件

后续如果有更多标注数据，可以考虑上深度学习方法，但现阶段规则基线已经足够说明问题。

### 踩过的一些坑

做这个项目过程中遇到不少问题，记录一下：

- **PDF清洗**：一开始以为pdfplumber直接提取就完了，结果发现页眉页脚、断行、参考文献全混在正文里，后来写了一套正则规则专门处理这些问题
- **CSV编码坑**：Neo4j的`LOAD CSV`对BOM头很敏感，我们用`utf-8-sig`生成的文件导入后属性全空，排查了好久才发现是BOM的问题，后来统一改成无BOM的`utf-8`
- **关系方向搞反**：一开始"并发症-疾病"和"疾病-并发症"都混在一起，后来统一规范成疾病当头实体，图谱才清晰起来
- **图谱不是完全连通**：126个实体里有11个从COPD出发走不到（比如一些孤立的中药名），这是正常的，毕竟不是所有实体都和COPD直接相关

## 实验设计与评价指标

### 消融实验

为了验证关系抽取方案的有效性，我们做了6个版本的递进式对比：

| 版本 | 说明 | 三元组数 | 关系类型数 | 模糊关系占比 |
|------|------|---------|-----------|------------|
| v1 原始规则 | 基础正则模板 | 131 | 4 | 0% |
| v2 清洗筛选 | 增加句子清洗+文献筛选 | 190 | 6 | 0% |
| v3 改进A | 仅保留句子清洗 | 163 | 4 | 0% |
| v4 最大覆盖 | 最大化关系覆盖 | 981 | 7 | 73.2% |
| v5 医学细化 | 医学知识审核细化 | 675 | 13 | 0% |
| v6 Final | 方向规范化+疾病统一在头 | 675 | 13 | 0% |

v4虽然召回高（981条），但73%都是"相关"这种模糊关系。经过医学审核后收敛到675条，关系类型从7种扩展到13种，模糊关系全部去除。

### 核心评价指标

| 指标类别 | 具体指标 | 结果 |
|---------|---------|------|
| 指南对齐度 | GOLD 2024核心推荐覆盖率 | 90.4%（47/52），药物/症状/危险因素/并发症均100%覆盖 |
| 数据质量 | 模糊关系占比 | Final版本经人工审核后，"相关"等模糊表述已去除 |
| 图谱规模 | 实体数/关系数/关系类型数 | 126实体 / 675关系 / 13种关系类型 |
| 图谱连通性 | COPD可达率 | 91.3%（115/126实体可从COPD出发2跳内到达） |
| 系统性能 | 文本处理速度/内存占用 | 约2000万字符/秒，峰值内存0.71MB |

详细评价报告见 `GOLD_COVERAGE_REPORT.md` 和 `EVALUATION_REPORT.md`。

2. **图谱未完全连通**：126个实体里有11个（8.7%）与COPD无直接路径，主要是一些中药名称。这属于合理范围，不影响核心诊疗路径展示。
3. **评估量表未覆盖**：mMRC评分、CAT评分等功能性评估工具未纳入当前抽取范围，后续可扩展"评估工具"实体类型。

## 怎么用

### 环境准备

- Python 3.10+
- Neo4j Desktop（可选，如果想看交互式图谱）

### 快速开始

```bash
# 1. 克隆仓库
git clone https://github.com/Yinik/COPD_REASERCH.git
cd COPD_REASERCH

# 2. 装依赖
pip install pdfplumber pandas python-docx py2neo networkx matplotlib

# 3. 一键验证数据完整性
python verify_project.py

# 4. 生成可视化图片
python generate_kg_viz.py

# 5. 启动Neo4j并导入（可选）
# 详见 关系抽取结果/Neo4j导入教程.md
```

Windows用户可以直接双击 `run_demo.bat`，会自动运行验证+生成图片+打开目录。

### 验证脚本会检查什么

运行 `python verify_project.py` 后，会输出5项检查结果：

1. 三元组是不是675条、13类关系
2. 126个实体的类型分布对不对
3. Neo4j导入文件齐不齐全
4. 图谱连通性（COPD能走到多少实体）
5. COPD是不是图谱的中心

如果全显示 `[PASS]`，说明数据没问题。
